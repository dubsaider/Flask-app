# Kanban Board

Веб-приложение для управления задачами в формате Kanban: доски, колонки, карточки, команды с настраиваемыми ролями, уведомления и rich-text в описаниях и комментариях.

## Возможности

- **Доски и колонки** — drag-and-drop карточек, настройка колонок (в т.ч. колонка «Done»)
- **Карточки** — приоритет, дедлайн, исполнитель, описание с форматированием (Quill)
- **Команды** — участники, куратор, настраиваемые роли и права доступа
- **Роли** — шаблоны (руководитель, разработчик, куратор) и создание своих ролей
- **Фильтры** — по исполнителю, приоритету, статусу на доске и в списке задач
- **Мои задачи** — сводный список назначенных задач
- **Дашборд** — статистика для руководителя (при наличии права `view_dashboard`)
- **Уведомления** — назначение задач, комментарии

## Стек

- **Backend:** Python, Flask, SQLite
- **ORM / миграции:** Flask-SQLAlchemy, Flask-Migrate (Alembic)
- **Frontend:** Jinja2, vanilla JavaScript, SortableJS, Quill

## Структура проекта

```
app.py              — точка входа, фабрика приложения
config.py           — конфигурация (env-переменные)
database.py         — подключение к SQLite для API
extensions.py       — db, migrate
models/
  domain.py         — DTO для ответов API
  schema.py         — SQLAlchemy-схема (источник для Alembic)
  seed.py           — демо-данные
api/                — REST API
web/                — страницы (Jinja2)
static/             — CSS, JS
templates/          — шаблоны
migrations/         — Alembic-миграции
```

## Быстрый старт

### 1. Клонирование и виртуальное окружение

```bash
cd Flask-app
python -m venv venv

# Windows
venv\Scripts\activate

# Linux / macOS
source venv/bin/activate
```

### 2. Зависимости

```bash
pip install -r requirements.txt
```

### 3. Конфигурация (опционально)

Скопируйте пример переменных окружения:

```bash
copy .env.example .env   # Windows
# cp .env.example .env   # Linux / macOS
```

Основные параметры — в `.env.example`. По умолчанию приложение использует `kanban.db` в корне проекта и применяет миграции при старте (`AUTO_MIGRATE=true`).

### 4. Запуск

```bash
# Вариант 1
python app.py

# Вариант 2
set FLASK_APP=app:create_app   # Windows
flask run
```

Приложение будет доступно по адресу: [http://127.0.0.1:5000](http://127.0.0.1:5000)

При первом запуске автоматически создаётся база и применяются миграции с демо-данными.

## Вход в систему

На странице `/login` выберите пользователя из списка (пароль не требуется — демо-режим).

| Пользователь | Роль в команде | Описание |
|--------------|----------------|----------|
| **charlie** | Руководитель | Полный доступ к доске, задачам и настройкам команды |
| **alice**, **bob** | Разработчик | Свои задачи, перемещение, комментарии |
| **diana** | Куратор | Просмотр и комментарии (назначена куратором команды 1) |
| **eve** | Руководитель | Команда Design Team |

После входа откроется первая доступная доска.

## Основные страницы

| URL | Описание |
|-----|----------|
| `/login` | Выбор пользователя |
| `/board/<id>` | Kanban-доска |
| `/tasks` | Мои задачи |
| `/dashboard` | Дашборд (для ролей с правом просмотра) |
| `/team/<id>/settings` | Настройки команды: роли и участники |

## Миграции базы данных

Схема описана в `models/schema.py`, изменения — через Alembic:

```bash
set FLASK_APP=app:create_app

flask db current              # текущая версия
flask db history              # история
flask db upgrade              # применить миграции
flask db migrate -m "описание"  # новая миграция после правки models/schema.py
```

Если база была создана **до** Flask-Migrate, один раз отметьте текущее состояние без применения SQL:

```bash
flask db stamp head
```

## Конфигурация

Настройки задаются в `config.py` и переопределяются переменными окружения:

| Переменная | По умолчанию | Назначение |
|------------|--------------|------------|
| `FLASK_CONFIG` | `development` | Профиль: `development`, `production`, `testing` |
| `FLASK_DEBUG` | `true` | Режим отладки |
| `FLASK_HOST` | `127.0.0.1` | Хост сервера |
| `FLASK_PORT` | `5000` | Порт |
| `SECRET_KEY` | dev-значение | Секрет Flask |
| `DATABASE_PATH` | `kanban.db` | Файл SQLite |
| `AUTO_MIGRATE` | `true` | Применять миграции при старте |

Публичные клиентские лимиты (rich-text) доступны через `GET /api/config`.

## API

REST API доступен по префиксу `/api/`:

- пользователи, команды, роли, доски, колонки, карточки
- комментарии, уведомления, задачи, дашборд

Примеры:

```
GET  /api/users
GET  /api/teams/<id>
GET  /api/boards/<id>/columns
POST /api/cards
PUT  /api/cards/<id>/move
```

Запросы, изменяющие данные, принимают `user_id` текущего пользователя в теле JSON.

## Разработка

После изменения `models/schema.py`:

```bash
flask db migrate -m "краткое описание"
flask db upgrade
```

Проверьте сгенерированный файл в `migrations/versions/` перед коммитом.
